# Energy Dashboard

ESP-IDF firmware for the Elecrow CrowPanel 1.46" round display (ESP32-S3, 8 MB PSRAM), with a UI designed in SquareLine Vision and rendered by LVGL 9.

## Layout

- `main/main.cpp` — board bring-up (display, touch, backlight) and the LVGL loop. Hand-written.
- `main/knob.c` — rotary knob via the PCNT hardware counter (encoder A = GPIO45, B = GPIO42; button GPIO41, active low). Hand-written. `KNOB_COUNTS_PER_STEP` sets counts per detent.
- `main/home_clock.c` — updates `GUI_Label__Home__{Hours,Divider,Minutes}` from the POSIX system time (TZ Europe/Amsterdam, blinking colon). Hand-written. Boots at 00:00 until SNTP (started by `wifi_manager` on connect) sets the time.
- `main/price.c` — parses a Tibber `priceInfo` response (cJSON, `espressif/cjson`) into a table of today + tomorrow quarters (`startsAt` → UTC `time_t`), picks the current quarter by time (`price_at`), and decides the trend: average of the next 8 quarters vs current; within ±2 % equal, beyond ±10 % hard up/down. No LVGL. Hand-written. `fixtures/priceInfo.json` shows the response format (not embedded).
- `main/tibber.c` — background task that POSTs the GraphQL query (`priceInfo(resolution: QUARTER_HOURLY)`, today + tomorrow) to `https://api.tibber.com/v1-beta/gql` with the NVS token: about hourly, right away when the token changes, backoff with jitter on errors, no retries on an invalid token. No LVGL; the UI polls `tibber_prices_generation()`/`tibber_get_status()`. Sets cJSON's allocator to prefer PSRAM. Hand-written.
- `main/home_price.c` — shows the price on `GUI_Label__Home__Price` as cents with 1 decimal ("143,6") and shows one of the 5 trend variants (`ui_Home_Price_Trend_{Down_High,Down,Equal,Up,Up_High}`), hiding the others. Redraws on new data and at each quarter boundary; `--` and no icon until there are prices and the clock is synced. Hand-written.
- `main/settings_store.c` — NVS namespace `cfg`: `wifi_ssid`, `wifi_pass`, `tibber_token`. Never log password/token values. Hand-written.
- `main/wifi_manager.c` — WiFi state machine: saved network → STA with backoff; no saved network, or no connection 60 s after boot → setup mode (APSTA hotspot `EnergyDashboard-XXXX`, random password). Credentials are tested before being saved. Starts SNTP on connect. WiFi events run in the event-loop task: never call LVGL from there; the UI polls `wifi_manager_get_state()/get_info()`. Hand-written.
- `main/setup_portal.c` + `main/web/setup.html` — captive-portal setup page (Dutch): `/`, `/scan`, `/save`, `/status`, 404 → redirect. DNS server copied from ESP-IDF's captive_portal example into `components/dns_server`. Hand-written.
- `main/screen_setup.c` — WiFi_Setup screen: `lv_qrcode` (WiFi-join QR for the hotspot) inside `GUI_Container__WiFi_Setup__QR_Container`, `Status` text, `Cancel_Button` (shown only with a saved network). Polls `wifi_manager` and switches to WiFi_Setup when setup opens, back to Home when it closes. Holding the knob button 5 s opens setup. Hand-written.
- `main/screen_settings.c` — Settings screen: `GUI_Label__Settings__WiFi_Info` (network + IP); Tibber status as an `lv_led` created in `Status_Led_Container` (SquareLine has no LED widget: green OK, orange no/invalid token, red no connection/error) plus text in `Tibber_Info`; `WiFi_Reset_Button` → `wifi_manager_start_setup()`. Back button and the Home gear button are SquareLine events. Hand-written.
- `main/background_rotator.c` — fades the Home background images every 60 s, and on knob turns while Home is active. Hand-written. Its rotation list uses the SquareLine widget names `GUI_Image__Home__{Eclipse,Aurora,Bol,Corsica}`: when a background is added or renamed in SquareLine, update that list (a renamed widget fails the build, so it can't break silently).
- `main/GUI/` — **generated by SquareLine Vision**. Never hand-edit; changes are lost on the next export.
- `CMakeLists.txt`, `sdkconfig`, `sdkconfig.defaults` — hand-maintained; contain fixes the GUI export must not overwrite.

## SquareLine component variants

SquareLine Vision exports each **variant** of a component as a separate component (`components/price_trend_up_component.c`, `ui_Price_Trend_Up_create()`, …), and each variant placed on a screen as its own instance variable. Code switches variants by showing one instance and hiding the others. Variant assets (e.g. the chevron SVGs) are only exported once the variants are placed on a screen.

## LVGL configuration

`CONFIG_LV_CONF_SKIP=y`: LVGL is configured through `sdkconfig` (Kconfig), **not** `main/lv_conf.h`. Edits to `lv_conf.h` have no effect. Put persistent LVGL settings in `sdkconfig.defaults` as well as `sdkconfig`.

## Updating the GUI from a SquareLine Vision export

SquareLine Vision exports UI files to a folder like `C:\Projects\Prive\Energy Dashboard_UIFiles_export<YYYYMMDDhhmm>`. The folder's contents map 1:1 onto `main/GUI/` (no `GUI` subfolder inside it).

1. Check the export contains only GUI files (`GUI.h`, `CMakeLists.txt`, `filelist.txt`, `assets/`, `behavior/`, `components/`, `core/`, `helpers/`, `screens/`). If it also contains `main.cpp`, `sdkconfig*`, `lv_conf.h` or a project-level `CMakeLists.txt`, do **not** copy those.
2. Diff the export against `main/GUI/` (`diff -r`) and summarize what changed.
3. Move the old `main/GUI/` out of the project as a backup (don't just overwrite). `main/CMakeLists.txt` globs every `.c` under `GUI/`, so stale files from an older export would still be compiled.
4. Copy the export folder's contents to `main/GUI/`.
5. Remove `THORVG_SETUP.md` from `main/GUI/` — it is a readme. Its required LVGL options (`LV_USE_FLOAT`, `MATRIX`, `VECTOR_GRAPHIC`, `THORVG`, `THORVG_INTERNAL`, `SVG`) are already in `sdkconfig.defaults`; check for any new ones.
6. Build and flash: `idf.py build flash monitor`.

## Known gotchas

- **SVG colors:** LVGL's SVG decoder draws vectors directly and ignores `image_recolor`. The colors in the source `.svg` are what appears on screen. Fix colors in the source SVG and re-export; for runtime recoloring use PNG assets or one SVG per color.
- **Dark theme:** `GUI_initTheme()` uses the dark default theme, so black SVG strokes are invisible.
- **LVGL memory:** LVGL uses the C heap (`CONFIG_LV_USE_CLIB_MALLOC=y`, spills into PSRAM). The 64 KB builtin pool ran out while rendering SVGs.
- **Silent hangs:** a failed LVGL assert spins in `while(1)` and only shows up as a task-watchdog error on IDLE0. Keep `CONFIG_LV_USE_LOG=y` so the assert message is printed.
- **Tick rate:** `CONFIG_FREERTOS_HZ=100` (10 ms ticks), so `pdMS_TO_TICKS(x)` is 0 for x < 10. Never pass 0 to `vTaskDelay` in a loop.
- **LVGL log format warnings:** the root `CMakeLists.txt` adds `-Wno-error=format` to the LVGL component, because LVGL's own log calls use `%u` for `uint32_t`.
